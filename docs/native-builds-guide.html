Build Vim, Git, ripgrep, and Ctags for your Apple CPU with Homebrew

How to make Homebrew itself compile four everyday tools with -O3 -mcpu=apple-mN, from M1 to M6, using a local tap so the tuned build survives brew upgrade. One script does it; every manual step is spelled out too.

What you get

Homebrew ships every Apple Silicon Mac the same bottle: a binary compiled for a generic ARMv8 baseline so it runs on an M1 and an M6 alike. Your Mac has exactly one CPU, and the compiler knows its instruction set, its pipeline widths, and its scheduling model. Passing -mcpu=apple-m4 (or whichever generation you have) lets clang and rustc use that knowledge.

This guide rebuilds four tools this way: Vim, Git, ripgrep, and Universal Ctags. Unlike the earlier experiment, which compiled outside Homebrew and swapped the binary into the keg, this approach makes Homebrew do the build from a formula you control. That has two practical consequences:

  • the Homebrew receipt is truthful: brew info shows a source build from your tap, not a bottle;
  • brew upgrade rebuilds from your formula instead of silently replacing the tuned binary with a bottle.

Expect gains in CPU-bound work: Vim regex and Vimscript loops measured 15-23% faster on an M4; Ctags parsers and ripgrep's Unicode regex improved in the earlier measurements. Memory-bound work and Git's everyday commands move little. The measurements page has the numbers; this page is only about how to do it.

Why Homebrew fights you

The obvious command does not work:

CFLAGS="-O3 -mcpu=apple-m4" brew reinstall --build-from-source vim   # generic build

Homebrew builds inside superenv, an environment that replaces clang with a shim at /opt/homebrew/Library/Homebrew/shims/mac/super/cc. Reading that shim explains the failure:

  • it deletes CFLAGS, LDFLAGS and friends from the environment before the build starts;
  • it strips -O*, -mcpu=* and -mtune=* from every compiler invocation, even ones the formula itself passes;
  • it then appends its own -Os plus an architecture flag from HOMEBREW_OPTFLAGS, which on Apple Silicon is an empty string. The Homebrew source carries the comment # TODO: -mcpu=apple-m1 when we've patched all our GCCs to support it;
  • the old escape hatch brew install --env=std now aborts with Calling brew install --env is disabled! Use env :std in specific formula files instead.

The last line is the way in. A formula can declare env :std, and Homebrew then builds it with stdenv: the real /usr/bin/clang, no shim, and a CFLAGS variable the formula can append to. So the recipe is: copy the official formula, add env :std and the flags, put it in a tap of your own, and let brew install --build-from-source do the rest.

Why not just edit the core formula? brew edit vim modifies homebrew-core, and the next brew update either reverts it or leaves the tap dirty. A local tap keeps your changes separate, versionable, and visible in brew info.

Which CPU name to use, M1 to M6

Clang identifies Apple CPUs by generation. Pro, Max, and Ultra variants of a generation share the same cores as the base chip, so they use the same name. Apple clang 21 (Xcode 26.2 Command Line Tools) knows all of these:

Chip familyVariants covered-mcpu / target-cpu valueBrand string starts with
M1M1, M1 Pro, M1 Max, M1 Ultraapple-m1Apple M1
M2M2, M2 Pro, M2 Max, M2 Ultraapple-m2Apple M2
M3M3, M3 Pro, M3 Max, M3 Ultraapple-m3Apple M3
M4M4, M4 Pro, M4 Maxapple-m4Apple M4
M5M5, M5 Pro, M5 Maxapple-m5Apple M5
M6M6 and variantsapple-m6Apple M6

You do not need to look it up by hand. Ask the compiler what native resolves to on this machine:

sysctl -n machdep.cpu.brand_string
# Apple M4

clang -mcpu=native -### -x c /dev/null 2>&1 | grep -oE '"-target-cpu" "[^"]+"'
# "-target-cpu" "apple-m4"

clang --print-supported-cpus 2>&1 | grep -oE 'apple-m[0-9]+' | sort -V | tr '\n' ' '
# apple-m1 apple-m2 apple-m3 apple-m4 apple-m5 apple-m6

Use the concrete name (apple-m4) rather than native in the saved formula. It makes the build reproducible on a different machine, it shows up verbatim in vim --version, and you can spot immediately when a formula was generated on an older Mac.

If your clang is older than your chip A new Mac with old Command Line Tools may not know its own CPU: -mcpu=native then resolves to the newest generation that clang supports. Update Xcode or the Command Line Tools first (softwareupdate --list), or set NATIVE_CPU=apple-m5 explicitly and accept that the compiler tunes for the closest generation it knows.

Do not use -march=armv9.2-a as a substitute. Generic ARMv9 profiles enable SVE, which Apple cores do not implement, and auto-vectorized code can then crash with an illegal instruction. -mcpu=apple-mN enables exactly the features the chip has.

Prerequisites

  • An Apple Silicon Mac (uname -m prints arm64) with Homebrew in /opt/homebrew.
  • Xcode Command Line Tools recent enough to know your CPU (see above). xcode-select --install if clang is missing.
  • For ripgrep: Homebrew's rust formula is installed automatically as a build dependency. The build uses that cargo, not rustup.
  • Python 3, which macOS ships, for the formula-patching step in the script.
  • The dot-files repository checked out, for the script and the saved formulas.

Build times on an M4 with 10 cores: Vim about 30 s, Git about 15 s, ripgrep about 40 s (fat LTO), Ctags about 20 s. Nothing needs to be uninstalled ahead of time; the script handles that.

The one-command path

bootstrap/native/brew_native.sh performs every step below for all four tools:

cd ~/dot-files
./bootstrap/native/brew_native.sh                  # vim git ripgrep universal-ctags
./bootstrap/native/brew_native.sh vim ripgrep      # a subset
./bootstrap/native/brew_native.sh --formulas-only  # refresh formulas/*.rb without building
NATIVE_CPU=apple-m3 ./bootstrap/native/brew_native.sh   # override CPU detection

It resolves the CPU name, creates the marian/local tap if needed, regenerates each formula from the current homebrew-core version, saves it to bootstrap/native/formulas/, syncs it into the tap, uninstalls the existing keg, installs from source, pins, and prints a verification summary. Rerunning it after a Homebrew update is how you pick up a new upstream version.

Change TAP=you/local if you fork the repository; the tap name only has to be unique on your machine.

The manual path, step by step

Vim is used as the worked example. The same steps apply to the other three; their formula edits are in the next section.

1. Find your CPU name

CPU=$(clang -mcpu=native -### -x c /dev/null 2>&1 | grep -oE '"-target-cpu" "[^"]+"' | cut -d'"' -f4)
echo "$CPU"   # apple-m4

2. Create a local tap once

brew tap-new --no-git marian/local
brew --repo marian/local        # /opt/homebrew/Library/Taps/marian/homebrew-local

--no-git skips initialising a git repository inside the tap; the formulas are versioned in dot-files instead.

3. Copy the official formula into the tap

cp "$(brew formula homebrew/core/vim)" "$(brew --repo marian/local)/Formula/vim.rb"

brew formula prints the path of the formula file Homebrew is currently using, whether it came from the JSON API cache or a full homebrew-core checkout.

4. Edit the formula

Three edits, in order:

  1. Delete the bottle do ... end block. Without it Homebrew never considers pouring a bottle, so plain brew install and brew upgrade build from source automatically.
  2. Add env :std on its own line above def install. This is the switch from superenv to stdenv.
  3. Add the flags as the first line inside def install: ENV.append_to_cflags "-O3 -mcpu=apple-m4". stdenv pre-populates CFLAGS with -Os -w -pipe; appending puts -O3 last, and the last -O flag wins.

For Vim, two more lines make the flags visible on the intro screen and in :version. Replace "--with-compiledby=Homebrew", in the configure arguments with:

"--with-compiledby=native-apple-m4",
"--with-modified-by=[ apple-m4 :: -O3 -mcpu=apple-m4 ]",

The result, abbreviated:

class Vim < Formula
  desc "Vi 'workalike' with many additional features"
  homepage "https://www.vim.org/"
  url "https://github.com/vim/vim/archive/refs/tags/v9.2.1100.tar.gz"
  sha256 "..."
  license "Vim"
  # (bottle block removed)

  depends_on "gettext"
  depends_on "libsodium"
  # ...

  env :std

  def install
    ENV.append_to_cflags "-O3 -mcpu=apple-m4"
    # ... unchanged core install body ...
    system "./configure", "--prefix=#{HOMEBREW_PREFIX}",
                          # ...
                          "--with-compiledby=native-apple-m4",
                          "--with-modified-by=[ apple-m4 :: -O3 -mcpu=apple-m4 ]",
                          # ...
  end
end

5. Save a copy you can commit

cp "$(brew --repo marian/local)/Formula/vim.rb" ~/dot-files/bootstrap/native/formulas/vim.rb

6. Uninstall the core keg, then install from the tap

brew unpin vim 2>/dev/null
brew uninstall --ignore-dependencies vim
brew install --build-from-source marian/local/vim
Do not use brew reinstall marian/local/vim here When the installed keg came from homebrew-core, brew reinstall resolves the formula from the keg's receipt and rebuilds the core formula under superenv, even though its output says "Reinstalling marian/local/vim". You get a fresh generic binary and a receipt that still says homebrew/core. Uninstalling first forces install to resolve the tap formula. Once the keg is from the tap, reinstall and upgrade behave.

--ignore-dependencies stops Homebrew from also removing packages that only vim depends on (it took libsodium along the first time). They come back with the install either way.

7. Pin it

brew pin vim

Pinning is belt-and-braces. Since the tap formula has no bottle, an upgrade would rebuild from source with your flags anyway, but the pin makes the intent explicit and stops brew upgrade from touching it until you decide to.

Per-tool details

Vim

Autotools; configure reads CFLAGS from the environment. Besides the cflags line, set --with-compiledby and --with-modified-by as shown above. All optional interpreters (Python 3, Lua, Ruby, Perl) and +sodium, +clipboard, +terminal survive unchanged because the rest of the install body is the core formula's.

Git

Git's Makefile takes CFLAGS=#{ENV.cflags} as an argument, and the core formula already passes it, so ENV.append_to_cflags is the only edit. The build also compiles git-credential-osxkeychain, git-subtree, and diff-highlight with the same flags. Git does not embed its compile flags anywhere; verification relies on the install receipt.

ripgrep

Rust ignores CFLAGS. Two edits inside def install:

env :std

def install
  ENV["RUSTFLAGS"] = "-C target-cpu=apple-m4"
  ENV.append_to_cflags "-O3 -mcpu=apple-m4"   # for the bundled pcre2 C build
  system "cargo", "install", "--profile", "release-lto", *std_cargo_args(features: "pcre2")
  # ...
end

release-lto is a profile ripgrep's own Cargo.toml defines for its release binaries: fat LTO, one codegen unit, panic = "abort", stripped symbols. Homebrew's default uses the plain release profile. The PCRE2 feature stays on, so rg -P keeps working.

Universal Ctags

Autotools with std_configure_args; the cflags line is the only edit. The build links against Homebrew's jansson, libyaml, and pcre2 bottles, which stay generic; only the ctags parsers themselves are tuned.

Dependencies that are pulled in during the build (rust, asciidoctor, jansson, and so on) are installed as normal bottles. Only the four formulas in the tap are compiled.

Verifying the build

Vim tells you directly:

vim --version | head -5
# VIM - Vi IMproved 9.2 (2026 Feb 14, compiled Sep 14 2026 17:58:36)
# macOS version - arm64
# Included patches: 1-1100
# Modified by [ apple-m4 :: -O3 -mcpu=apple-m4 ]
# Compiled by native-apple-m4

vim --version | grep -o 'Compilation:.*' | grep -oE -- '-O[0-9s]|-mcpu=[a-z0-9-]+'
# -Os
# -O3
# -mcpu=apple-m4

For all four, the install receipt is the authoritative record. A tuned build shows your tap, no bottle, and a formula path inside the tap:

for f in vim git ripgrep universal-ctags; do
  printf '%-16s' "$f"
  python3 -c '
import json, glob, sys
r = json.load(open(glob.glob(f"/opt/homebrew/Cellar/{sys.argv[1]}/*/INSTALL_RECEIPT.json")[0]))
print(r["source"]["tap"], "bottle=%s" % r["poured_from_bottle"], r["source"]["path"])' "$f"
done
# vim             marian/local bottle=False /opt/homebrew/Library/Taps/marian/homebrew-local/Formula/vim.rb
# git             marian/local bottle=False /opt/homebrew/Library/Taps/marian/homebrew-local/Formula/git.rb
# ripgrep         marian/local bottle=False /opt/homebrew/Library/Taps/marian/homebrew-local/Formula/ripgrep.rb
# universal-ctags marian/local bottle=False /opt/homebrew/Library/Taps/marian/homebrew-local/Formula/universal-ctags.rb

If a line says homebrew/core bottle=True after you built it, you hit the reinstall pitfall above: uninstall and install again.

A quick smoke test after each build is worth the ten seconds:

vim -Es +'echo "ok"' +q && echo vim ok
git -C ~/dot-files status --short >/dev/null && echo git ok
rg -P '(?<=brew )pin' ~/dot-files/README.md >/dev/null && echo rg pcre2 ok
ctags --list-languages | wc -l

The benchmarks/ directory has the harnesses from the measurements page if you want numbers rather than a smoke test.

Upgrading later

Because the tap formula is a snapshot of homebrew-core at the time you generated it, brew outdated will not report a newer upstream Vim until the tap formula changes. The upgrade procedure is: refresh Homebrew, regenerate, rebuild.

brew update
./bootstrap/native/brew_native.sh vim          # copies the new core formula, patches, builds, pins
git -C ~/dot-files diff bootstrap/native/formulas/vim.rb   # see what upstream changed
git -C ~/dot-files commit -am "chore(native): vim 9.2.1200"

By hand, that is steps 3 to 7 again. Compare the freshly copied core formula with your saved one before rebuilding; if upstream changed the configure arguments or the install body, make sure your three edits still land in the right place. The script asserts that def install exists and that the Vim --with-compiledby replacement matched, and refuses to continue otherwise.

The same flow works when you move to a new Mac: run the script once and the formulas are regenerated with the new chip's name. The committed .rb files record which generation they were built for.

Restoring stock bottles

Going back is one line per tool. Naming the core formula explicitly avoids ambiguity with the tap:

for f in vim git ripgrep universal-ctags; do
  brew unpin "$f"
  brew uninstall --ignore-dependencies "$f"
  brew install "homebrew/core/$f"
done
brew untap marian/local      # optional; removes the tap and its formulas

Pitfalls

  • brew reinstall from a core keg builds the core formula. Covered above; it is the one that bit hardest because the build visibly runs and succeeds.
  • The vim --version Compilation line does not prove anything under superenv. The shim injects its flags invisibly, so a superenv build shows -g -O2 from Vim's own Makefile and nothing about -mcpu. Only under stdenv does the line show what clang actually received.
  • brew uninstall autoremoves orphaned dependencies unless you pass --ignore-dependencies. Harmless, since the install brings them back, but surprising in the output.
  • HOMEBREW_NO_INSTALL_FROM_API=1 is not needed for tap formulas; they are always loaded from the tap directory. It only matters if you want brew formula homebrew/core/vim to come from a full core checkout instead of the API cache. Both produce the same file.
  • Only Vim exposes its flags. Git, ripgrep, and ctags have no equivalent of --with-compiledby. Trust the receipt and the tap path, or disassemble and look for instructions your generation added.
  • The tuned binary is not portable. A binary built with -mcpu=apple-m4 may use instructions an M1 lacks. Do not copy the Cellar to another Mac; regenerate there.
  • Rosetta and Intel Macs are out of scope. The script exits unless uname -m is arm64.
